## Before you begin

You need a sandbox Bearer key and the non-sensitive `clientCode` granted to that Integration. Never use production personal data while testing.

<Steps>
  <Step title="Choose stable identifiers">
    Use an opaque source-record ID containing 1–128 letters, digits, underscores, or hyphens. Do not put member numbers, account numbers, names, emails, or phone numbers in a URL.
  </Step>
  <Step title="Place a Party">

    ```bash
    curl --request PUT \
      --url https://api.sandbox.paypathiq.com/v1/clients/CU_DEMO/parties/PTY_123 \
      --header 'Authorization: Bearer ppiq_test_your_key' \
      --header 'Content-Type: application/json' \
      --data '{
        "type": "person",
        "name": {
          "givenName": "Avery",
          "familyName": "Example"
        },
        "sourceReference": "member-ref-example",
        "emails": [
          {
            "address": "avery@example.test",
            "type": "personal",
            "isPrimary": true
          }
        ]
      }'
    ```
  </Step>
  <Step title="Read it back">

    ```bash
    curl --request GET \
      --url https://api.sandbox.paypathiq.com/v1/clients/CU_DEMO/parties/PTY_123 \
      --header 'Authorization: Bearer ppiq_test_your_key'
    ```

    The first successful `PUT` returns `201 Created`. An update or identical retry returns `200 OK`.
  </Step>
</Steps>

<Tip>
  Lose a response after sending a request? Repeat the same request or `GET` the resource. Stable URLs and normalized payload digests make identical retries safe.
</Tip>
